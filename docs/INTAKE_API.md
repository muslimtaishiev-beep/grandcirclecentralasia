# Приём заявок и бронирование — API для внешнего сайта

Документ самодостаточный: чтобы построить сайт регистрации, больше ничего знать не нужно.

## Что это такое

Набор адресов, куда ваш сайт отправляет заявки людей и запросы на бронирование. Всё, что связано с хранением, лимитами мест и защитой от двойной брони, берёт на себя наш сервер — сайту остаётся форма и экраны.

**Что API позволяет сделать:**

- **принимать регистрации** в любой форме, которую вы сверстаете: платформа не диктует ни полей, ни их набора. Обязательны только контакты человека (имя и почта или телефон), всё остальное — ваша структура любой вложенности: состав команды списком, ветвление, свои проверки;
- **вести несколько независимых потоков приёма** — например, отдельно команды, отдельно одиночные участники, отдельно коворкинг, у каждого свои сроки и лимит заявок;
- **бронировать ограниченные места**: место участника, стол, зону, слот времени у ментора. Места не «перебронируются»: если два человека нажали на последнее одновременно, получит его ровно один;
- **собирать команды**: участник создаёт команду, получает короткий код, остальные вступают по нему. Каждый участник регистрируется сам, поэтому у каждого свой пропуск;
- **возвращать человека к его заявке** по ссылке с кодом — без паролей и личного кабинета. По ней он видит свой статус, свои брони и может их менять.

**Чего API не делает:** не присылает письма, не принимает оплату, не хранит файлы (резюме и презентации передавайте ссылками), не ведёт лист ожидания. Заявки после подачи обрабатывает организатор в своём кабинете.

**Чем это отличается от обычной формы.** Форма просто собирает ответы. Здесь за ответами стоит учёт мест: сервер знает, сколько занято, кто что занял и кому уже нельзя.

Сайт делает обычные `fetch`-запросы к нашему серверу. Никаких библиотек, ключей и авторизации не требуется — человек опознаётся по ссылке с кодом, которую получает после подачи заявки.

**Адрес сервера:** `https://www.studyfreeforum.com`
**Все ответы:** JSON вида `{"success": true, ...}` либо `{"success": false, "error": "текст для человека"}`. Текст ошибки написан по-русски и его можно показывать пользователю как есть.

## Прежде чем начать

Организатор должен сообщить две вещи:

1. **Адрес вашего сайта внесён в список разрешённых.** Пока этого нет, любой запрос из браузера вернёт `403` с текстом «Этот сайт не подключён к организации». Адрес указывается точно, со схемой и без косой черты в конце: `https://hackathon.example.com`. Для локальной разработки попросите добавить и `http://localhost:3000`.
2. **Идентификатор потока приёма** (`streamId`) — строка вида `k3Jd8slAqm2...`. Потоков может быть несколько: например, отдельно регистрация команд, отдельно одиночных участников, отдельно коворкинг. У каждого свой идентификатор, свои правила и свой лимит мест.

### Настройки потока, от которых зависит ваш сайт

Их задаёт организатор, вы только читаете. Часть приходит в ответе `GET /stream/{streamId}`, часть влияет молча — если не знать о ней, поведение выглядит необъяснимым.

| Настройка | Что делает | Как узнать |
|---|---|---|
| `requireApproval` | бронирование открывается только после одобрения заявки | приходит в ответе |
| `maxBookingsPerEntry` | сколько мест может занять один человек | приходит в ответе (`null` — без ограничения) |
| `capacity` потока | предел числа заявок; когда исчерпан, приём закрывается сам | видно по `free` и `closed` |
| `allowParticipantResources` | разрешено ли участникам создавать свои места (так делаются команды) | **в ответе не приходит** — спросите организатора |
| `allowedResourceIds` | какие именно места доступны из этого потока | **в ответе не приходит** — список уже отфильтрован в `/resources` |

Если `allowParticipantResources` выключено, запрос создания команды вернёт `403` с текстом «Создание недоступно» — это настройка, а не ошибка вашего кода. Спросите организатора, включено ли оно, прежде чем рисовать кнопку «создать команду».

## Готовые идентификаторы для хакатона

Заведены и проверены. Названия, числа и сроки организатор меняет у себя — идентификаторы при этом не меняются.

| Поток приёма | `streamId` | Особенности |
|---|---|---|
| Регистрация команды | `2SMvd17Zb7fBEU9f8UVS` | участник может создать команду (до 5 человек), до 3 мест на человека |
| Одиночная регистрация | `Ng0s4KXeSh82t1Sx5kI2` | создавать команды нельзя, можно вступить по коду |
| Коворкинг | `UI7y2QNH04uMjYIakPRC` | **только после одобрения** организатором, 40 заявок, 1 место на человека, доступны лишь зоны |

Что можно занимать: «Место участника» (150), «Зона A» и «Зона B» (по 24), три слота питчей по одному месту. Список приходит запросом `/stream/{streamId}/resources` — не вшивайте его в код, свободные места меняются на ходу.

**Разрешённые адреса сайта** сейчас: `http://localhost:3000` и `http://localhost:5173`. Боевой домен нужно добавить до запуска, иначе браузер получит `403`.

## Порядок работы

```
1. GET  /stream/{streamId}            → узнать, открыт ли приём
2. POST /stream/{streamId}/submit     → отправить заявку, получить код
3. сохранить код и дать ссылку человеку
4. GET  /my/{код}                     → что человек уже занял и что свободно
5. POST /my/{код}/book                → занять место
```

## 1. Проверить, открыт ли приём

```
GET /api/intake/public/stream/{streamId}
```

```json
{
  "success": true,
  "org": { "name": "Название организации", "logoUrl": null, "primaryColor": "#0F62FE" },
  "stream": {
    "id": "k3Jd8slAqm2",
    "title": "Регистрация участников",
    "description": "",
    "closed": false,
    "closedReason": null,
    "requireApproval": false,
    "maxBookingsPerEntry": null,
    "free": 120,
    "opensAt": null,
    "closesAt": null
  }
}
```

- `closed: true` — приём закрыт, в `closedReason` человекочитаемая причина («Приём заявок ещё не начался», «Свободных мест не осталось»). Покажите её и не рисуйте форму.
- `requireApproval: true` — бронировать можно **только после того, как организатор одобрит заявку**. Предупредите об этом на экране благодарности.
- `free` — сколько заявок ещё примут; `null` означает, что лимита нет.

## 2. Отправить заявку

```
POST /api/intake/public/stream/{streamId}/submit
Content-Type: application/json
```

**Форму вы верстаете сами, какую хотите.** Мы не диктуем ни поля, ни их порядок, ни оформление. От вас нужны только контакты — по ним организатор находит человека и связывается с ним. Всё остальное кладите в `answers` в любой удобной структуре.

```json
{
  "contact": {
    "name": "Иван Иванов",
    "email": "ivan@example.com",
    "phone": "+996 555 123456"
  },
  "answers": {
    "track": "Искусственный интеллект",
    "experience": "3 года",
    "team": [
      { "name": "Иван", "role": "бэкенд", "github": "https://github.com/ivan" },
      { "name": "Мария", "role": "дизайн", "github": "https://github.com/maria" }
    ],
    "needsHardware": true,
    "tshirt": "L",
    "agreedToRules": true
  }
}
```

**Обязательно:** `contact.name` и хотя бы одно из `contact.email` / `contact.phone`.
**Свободно:** всё содержимое `answers` — вложенные объекты, массивы, числа, галочки.

Ответ:

```json
{ "success": true, "token": "K7M2QP9XRT4WVBNH", "entryId": "...", "requireApproval": false, "message": "Заявка принята." }
```

`token` — код человека. **Сохраните его** (в `localStorage` и, если можно, отправьте человеку на почту ссылкой вида `https://ваш-сайт/my?code=K7M2QP9XRT4WVBNH`). Другого способа вернуться к своей брони нет: паролей и личных кабинетов в этой схеме не существует.

Если человек отправит форму дважды, второй раз придёт `{"success": true, "duplicate": true, "token": "тот же код"}` — новой заявки не создаётся, место не занимается второй раз.

### Рамки для `answers`

| Ограничение | Значение | Что будет при нарушении |
|---|---|---|
| Глубина вложенности | до 5 уровней | `400` |
| Всего полей | до 100 | `400` |
| Длина одного текста | до 5000 символов | `400` |
| Элементов в списке | до 50 | `400` |
| Вся заявка | до 700 КБ | `413` |

**Файлы не принимаются.** Резюме, презентации и логотипы загружайте куда угодно (Диск, GitHub, ваш хостинг) и присылайте обычной строкой-ссылкой. Строка, начинающаяся с `data:`, будет отклонена с текстом «Файлы в заявке не принимаются — пришлите ссылку на файл».

## 3. Что можно занять

```
GET /api/intake/public/stream/{streamId}/resources
```

```json
{
  "success": true,
  "resources": [
    { "id": "aBc123", "title": "Место участника", "group": "", "capacity": 200, "taken": 143, "free": 57, "startsAt": null, "endsAt": null, "createdByParticipant": false, "active": true },
    { "id": "dEf456", "title": "Стол №3", "group": "Столы", "capacity": 6, "taken": 6, "free": 0, "startsAt": null, "endsAt": null, "createdByParticipant": false, "active": true },
    { "id": "gHi789", "title": "Питч 14:00", "group": "Питчи", "capacity": 1, "taken": 0, "free": 1, "startsAt": {"_seconds": 1788000000}, "endsAt": null, "createdByParticipant": false, "active": true }
  ]
}
```

Всё, что можно занять, — однородный список. Место участника, стол, слот времени и команда отличаются только вместимостью, названием и группой. Группируйте на экране по полю `group`, показывайте `free`, блокируйте кнопку при `free === 0`.

Даты приходят как `{"_seconds": 1788000000}` — умножьте на 1000 для `new Date()`.

## 4. Личная страница участника

```
GET /api/intake/public/my/{token}
```

```json
{
  "success": true,
  "org": { "name": "...", "logoUrl": null, "primaryColor": null },
  "entry": {
    "id": "...", "token": "K7M2QP9XRT4WVBNH",
    "status": "new", "statusLabel": "Заявка принята",
    "contact": { "name": "Иван Иванов", "email": "ivan@example.com", "phone": "..." },
    "answers": { "...то, что вы прислали..." },
    "history": [ { "status": "new", "label": "Заявка принята", "at": {"_seconds": 1788000000} } ]
  },
  "stream": { "id": "...", "title": "Регистрация участников", "requireApproval": false },
  "canBook": true,
  "bookings": [
    { "id": "bk_aBc123_xyz", "resourceId": "aBc123", "resourceTitle": "Место участника", "group": "", "status": "active", "statusLabel": "Активна", "joinCode": null }
  ],
  "resources": [ "...как в пункте 3..." ]
}
```

- `canBook` — можно ли сейчас бронировать (учитывает статус заявки и требование одобрения). Если `false`, покажите пояснение из `entry.statusLabel`.
- `status`: `new` (принята), `approved` (одобрена), `rejected` (отклонена), `cancelled` (отменена).
- `bookings[].status`: `active` (место за человеком), `held` (организатор снял бронь — например, отклонил заявку), `cancelled` (человек отменил сам).

## 5. Занять место

```
POST /api/intake/public/my/{token}/book
{ "resourceId": "aBc123" }
```

| Ответ | Что означает | Что показать |
|---|---|---|
| `200` `{"result": "ok", "free": 56}` | место занято | подтверждение, обновить список |
| `200` `{"result": "already"}` | уже было занято этим человеком | ничего страшного, обновить список |
| `409` `{"result": "full"}` | места закончились | «Мест не осталось», обновить список |
| `409` `{"result": "closed"}` | запись сюда закрыта | сообщение из `error` |
| `409` `{"result": "limit"}` | исчерпан лимит на человека | сообщение из `error` |
| `403` | заявка ещё не одобрена или отклонена | сообщение из `error` |

**`full` — обычное дело, а не сбой.** Места заканчиваются, пока человек заполняет форму. Всегда обрабатывайте этот ответ: покажите сообщение и перезапросите список — свободное количество мгновенно меняется.

## Отменить

```
POST /api/intake/public/my/{token}/cancel
{ "resourceId": "aBc123" }
```

## 6. Команды

Команда — это то же самое «что-то с вместимостью», просто его создаёт участник, а не организатор. Если организатор разрешил создание, работает так:

**Капитан создаёт:**
```
POST /api/intake/public/my/{token}/create
{ "title": "Название команды", "capacity": 5, "description": "" }
```

`capacity` можно не передавать — тогда берётся размер, заданный организатором. Переданное значение приводится к диапазону от 1 до 100. Название обязательно.
```json
{ "success": true, "result": "ok", "joinCode": "X7K2M9", "resource": { "id": "...", "title": "Название команды", "capacity": 5, "taken": 1, "free": 4 } }
```
Капитан сразу занимает в ней место. `joinCode` — короткий код, который он передаёт своим.

**Остальные вступают:**
```
POST /api/intake/public/my/{token}/join
{ "joinCode": "X7K2M9" }
```
Ответы те же, что у бронирования: `ok`, `already`, `full` (команда набрана), `404` (код не найден).

Каждый участник команды регистрируется сам и получает свой код, свою страницу и своё место. Капитан не заполняет анкету за других.

## Ошибки

| Код | Причина | Действие |
|---|---|---|
| `400` | заявка не прошла проверку | показать `error` |
| `403` | сайт не в списке разрешённых, либо бронь ещё не открыта | если это про сайт — обратиться к организатору |
| `404` | неизвестный код, поток или ресурс | «Ссылка не найдена» |
| `409` | мест нет, лимит, повтор | показать `error`, обновить список |
| `410` | приём закрыт | показать `error` |
| `413` | заявка слишком большая | попросить сократить |
| `429` | слишком много запросов подряд | подождать минуту |

Ограничение частоты: 300 запросов за 15 минут с одного адреса. На обычную регистрацию этого хватает с большим запасом; не опрашивайте список мест в цикле — обновляйте его по действию человека.
